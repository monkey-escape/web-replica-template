# strict 与 adapt

每条路由在 `tests/parity/profiles/<site-id>.json` 里二选一。选择写在分析阶段，不要等测量失败后再改。

## strict

目标是 1:1。

- 结构列表的成员和顺序都要一致：地标、标题、组件、交互。
- 整页截图的差异像素比例必须不超过 `visual.strictMaxDiffRatio`，模板默认是 `0`。
- 档案里不能写 `accepted`。加载档案时会直接拒绝。
- 缺参考图、尺寸不一致、交互文本不对，都继续算失败。
- 循环退出码是 2 时，只能改克隆。不能把路由改成 adapt，不能提高阈值，不能在修复循环里重拍参考图。

适合：首屏、列表、详情、价格和导航这类用户会拿来对图的页面。

## adapt

目标仍然是对齐，但允许事先写明的差异。

- 结构上的每一处缺失、多余或乱序，都要在该路由的 `accepted` 里有对应的一条：`kind`、`key`、`item` 全中才算被接受。没写上的差异仍然失败。
- 像素差比例使用 `route.visual.maxDiffRatio`，没有则用 `visual.adaptMaxDiffRatio`（模板默认 `0.02`）。超过就失败。
- 接受一条差异之前，先在本文件的「允许的差异」里找到对应类别，并在 `analysis/overview.md` 写明为什么这条路由不能 strict。

适合：法律文案会随地区变化的页脚、必须换成自己账号的第三方挂件、登录后才存在而克隆阶段看不到的账户页。

## 允许的差异

只有这些类别可以做成 adapt，并且仍然要逐条写进 `accepted` 或接受像素阈值内的残余：

1. **法务与地区文案。** 目标站的法律、隐私、版权年份会被换成克隆方自己的句子。周围布局仍要 strict 级别地对齐。
2. **第三方挂件。** 目标站嵌入的聊天、支付或地图，克隆里改成同尺寸的占位，或换成克隆方自己的公开挂件。不要复制目标站的密钥。
3. **需要登录的页面。** 分析时看不到的账户内部，可以先做公开状态下的外壳。外壳本身能看到的部分仍然测量。
4. **模板演示。** `example` 的 `/about/` 多了一个 `template-notice`，用来说明 accepted diff 怎么写。真实站点不要留这个组件。

不在这四类里的差异，路由保持 strict。

## example 怎么对照

| 路由              | 模式   | 原因                                                                                   |
| ----------------- | ------ | -------------------------------------------------------------------------------------- |
| `/` `home`        | strict | 骨架首页。结构必须一致，点击 API 后状态文本必须包含 `API ok`，像素差为 0               |
| `/about/` `about` | adapt  | 教学用。`structure.json` 不包含 `template-notice`，档案接受这个额外组件。像素阈值 0.02 |

`about` 的 accepted 条目是：

```json
{ "kind": "extra", "key": "components", "item": "template-notice" }
```

首页如果多出一个组件，循环会以退出码 2 停住，因为 strict 路由写了 `accepted` 时档案本身就是非法的。
